# 0078.2 — The merger-dispatch proofs actually count dispatches

**Status:** blocked (deps-unmet) until 0078.1 lands — then flip to ready · **Depends on:** 0078.1 ·
**Raised:** 2026-08-04 (split from 0078; the maxed-out run's reviewer left this as the open blocker
`default-branch-race-retry-can-enter-merger` plus a dispatch-count false positive)

Contract (from 0078, binding): **never retry into model spend.** A race retry re-runs the
mechanical rebase only; if reconciliation genuinely needs the merger again, that is a park. The
landed implementation enforces this structurally — one mechanical-only state is set before every
race retry and consumed inside `merge_locked` — but the proofs that would catch a regression are a
false positive and a hole:

- **The counting-merger fixture cannot count.** `install_counting_merger`
  (`proof_merge_on_completion.rs`) records each dispatch by appending the bytes `call` with no
  separator, and the assertions count lines — one dispatch (`call`) and three (`callcallcall`)
  both read as one. `race_retry_conflict_parks_without_a_second_merger_dispatch` therefore passes
  even if a retry dispatches the merger repeatedly.
- **No public-path checkout-branch-probe proof exists.** The reviewer's done-when: force a
  checkout-branch probe race on the first attempt, arrange the retry to meet a divergent base that
  would need reconciliation, and prove the retry parks with the merger harness never invoked.

## Scope

Test-only, in `modules/cli/tests/proof_merge_on_completion.rs`:

- Make the fixture record one independently countable entry per dispatch (one line per dispatch is
  enough) and assert EXACTLY one entry after the reconciliation-required retry — an assertion that
  fails if a second dispatch is injected.
- Add the checkout-branch-probe public-path race proof described above, using the honest counting
  fixture as the instrument: zero merger dispatches across the retry-then-park.

No production code changes; if a proof can only pass by changing `merge.rs`, stop and say so — that
is a finding about the implementation, not a reason to widen this task.

## Done when

The counting-merger fixture distinguishes one dispatch from many;
`race_retry_conflict_parks_without_a_second_merger_dispatch` asserts exactly one dispatch; a
checkout-branch-probe race proof exists on the public path showing zero merger dispatches across
retry-then-park; `cargo test -p ctx-traits-cli --test proof_merge_on_completion` passes; the
per-round gate is green; landed on `main`.
