Park on command: callback completion

Corrected flow for the brainstorm trait's owner-acceptance gate: a command marked completion: "callback" is run by a tiny detached worker. The drive parks, and the worker owns execution and reliably forwards command evidence to the center. Success completes that exact frame and resumes the run; failure parks with diagnostic evidence until the user chooses retry or cancel. The markdown sibling of this file is the authoritative proposal text.

Annotations (not approval) route resumed → awaiting-agent-output: a revise frame applies them, then the callback command parks again. The existing 500-round backstop remains; waiting on an unfinished command spends no round.

Today, for contrast: the gate is a blocking command step. advance_commands holds the drive process, terminal, and worktree while the owner thinks; 10 minutes of silence trips the idle kill (DEFAULT_COMMAND_IDLE_MS), and the gate's fallback burns an acceptance-loop round. Callback completion releases the driver and terminal; the worker necessarily retains the command's worktree.
command / API call data return / notification drive parked — worker alive bounded revision loop
Remote runtime (future, not MVP): the worker and center can later communicate over a remote transport using the same one-use callback envelope. The first implementation stays machine-local: one Unix socket, one authoritative ledger, and one detached worker. After restart, a valid successful callback starts the normal drive. A callback TTL, command timeout, non-success exit, invalid output, spawn failure, or absent bound worker is a recoverable failure. The run stays parked and exposes the typed reason and available command evidence with only retry/cancel actions; it never automatically re-executes argv because the command may already have produced side effects.
