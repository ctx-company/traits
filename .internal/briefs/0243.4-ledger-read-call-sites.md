# 0243.4 Ledger Read Call Sites

This is an observed production-call inventory, not a test fixture. Line
numbers are intentionally omitted because this file is maintained with the
call rather than frozen to a revision.

## Center-owned shared-store reads

- `modules/io/src/center.rs::read_session`: the center's one-ledger parser.
- `modules/io/src/center.rs::discover_inner`: enumerates the runs-root stores
  with `session_store_paths` before reconciliation. This is the only remaining
  whole-store ledger scan.

## Writer and mutation protocol reads

- `modules/io/src/run.rs`: `start`, resume, answer, and drive-transition
  helpers reopen their selected authoritative ledger while writing its next
  state.
- `modules/io/src/run_session.rs`: the read-modify-write helpers (`record_*`,
  maintenance, and migration operations) reopen exactly their supplied path.
- `modules/cli/src/app/drive.rs`: driver setup, transition, and retry paths
  read their selected ledger as part of the writer-owned protocol.
- `modules/cli/src/app/merge.rs`: explicit-store resolution and the
  center-selected ledger's final pre-mutation validation reopen one path.
- `modules/io/src/run_session.rs::find_session_by_run_id`: scans only an
  explicit user-selected store for merge; default merge lookup is center-backed.
- `modules/cli/src/app/run.rs`: completion/mutation reporting reads the path
  it just drove.
- `modules/io/src/run_queue.rs::read_session`: selected-run queue transition
  read. `run_queue.rs::scan_store` only enumerates and partially deserializes
  `SessionProbe` for `run next`; it is not a session-state surface.

## Explicit detail reads

- `modules/cli/src/app/dashboard.rs::apply_session_action`: answer mutation
  reopens its locked authoritative ledger for TOCTOU validation before writing.
- `modules/cli/src/app/dashboard.rs::execute_confirmed_delete`: SESSIONS
  DELETE and MERGES DROP acquire maintenance ownership, then reopen one ledger
  to validate the selected session and artifact plan before removal.
- `modules/cli/src/app/dashboard.rs::apply_session_action` KILL: an unheld
   run acquires maintenance ownership and reads one authoritative ledger to
   validate its identity and current interrupt eligibility. Held runs use the
   holder metadata and validated control token, then reopen the selected
   authoritative ledger to verify that the holder still owns that session
   before requesting interruption.
- `modules/cli/src/app/dashboard.rs::build_attached_view`,
  `refresh_attached_view`, and preview reconstruction: selected attach/preview
  detail. The `dashboard/worker.rs` preview command channel from 0243.1(a)
  remains; it is not the deleted inventory cache.
- `modules/cli/src/app/dashboard.rs::build_story_view_from_center`: selected
  story reads the full cached session through `center::get`; it only reads the
  selected activity sidecar by path.
- `modules/cli/src/app/run_view.rs`: live/detail view refresh for a selected
  ledger.
- `modules/cli/src/app/story.rs`: explicit story command for its selected
  ledger.

## Declared exception

- `modules/io/src/run_liveness.rs::live_sessions_pinned_to_digest`: bounded
  per-live-row reads on the `trust --blocked` path. It must not spawn a center,
  so it remains an explicit exception.

## Dashboard model

- `modules/cli/src/app/dashboard/worker.rs` owns one machine-wide
  `center::subscribe(None)` stream, keeps its rows keyed by ledger path, and
  sends coalesced public-row projections to the renderer. Session refresh
  commands change only view scope and never reopen or scan a ledger.
- `modules/io/src/center.rs::refresh_after_probe` adopts held rows into the
  liveness index; this responsibility moved from the deleted dashboard sweep.
