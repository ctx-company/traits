# 0063.1 — Typed task fields: `content`, `scope`, `validation` (schema 0.1 → 0.2)

## What was built

The task document schema bumped from 0.1 to 0.2, splitting the opaque `content` blob into three typed prose fields and adding three optional envelope fields:

- `TaskDocument` (`modules/core/src/task/mod.rs`) gains `scope: String` (absorbs the house-convention `## Decisions` + `## Scope` sections) and `validation: String` (absorbs `## Watch` + `## Done when`), both `#[serde(default, skip_serializing_if = "String::is_empty")]`, plus `wall`, `origin`, and `closed` as `Option<String>`. Steps keep their single `content`.
- `TaskDocument::prose_sections()` is the single definition of the canonical rendering order (`content`, `scope`, `validation`), consumed now by `ctx tasks show` (`modules/cli/src/app/tasks.rs` prints each non-empty field as a labeled panel row) and intended for 0063.2's detail pane.
- `split_sections()` in `modules/core/src/task/markdown.rs` is the one header-partition algorithm, shared by the markdown importer and the (throwaway, uncommitted) board migrator so the two cannot diverge. Section headers are kept verbatim inside the absorbing field, preserving merged-section boundaries.
- The `**Wall:**` prose scrape is deleted from the dispatch path: `dispatch_preflight::explicit_wall_id` now returns `document.wall.clone()`; `WALL_LABEL`, `wall_label`, and their tests are gone from `modules/io/src/dispatch_preflight.rs`. Wall detection moved to import time in `markdown.rs`, restricted to a line-initial declaration (`trim_start().starts_with(WALL_LABEL)`) with removal keyed to a successfully parsed id — a prose mention or bare label line stays in `content`.
- `FilesTaskBoard::update` stamps `closed` with the host clock's UTC date (new `audit_journal::today_date_utc()`) only on a live → done/cancelled transition.
- The whole board — all 160 TOML files, live and archived — was migrated in the same change as the code bump; the parser stays single-version per standing doctrine.

Field rulings, recorded in the task file per its done-when: `wall` **accepted** (both prior `**Wall:**` occurrences on the board were quotes, so the migrated board carries zero typed wall values); `origin` **accepted as a dormant field** for 0064/0075 to write; `closed` **accepted**. The `content` → `description` rename was declined, as the plan's out-of-scope note allowed.

## Why

Renderers (`tasks show` now, the 0063.2 detail pane next) need to label and order a task's prose without parsing markdown headers, and the dispatch preflight was scraping load-bearing wall ids out of free prose. Typed fields delete that prose-parse and give 0064/0075 a place to write task provenance without a second schema bump.

## How it was validated

- Implementation evidence (worker, this round): `CARGO_TARGET_DIR=target just test` exits 0 — full workspace build, `sdk-generate --check`, all pnpm `format:check` stages, and the full cargo test suite (36/36 in `ctx-traits-core --lib task`, including the new `prose_mention_of_wall_label_is_not_a_declaration` test; 285/285 in `ctx-traits-io`).
- Migration gate (earlier rounds): the migrator enforced the order-safe strengthening of the task's zero-loss gate — whitespace-normalized line multiset of the three fields equals the old `content`'s, with relative order preserved within each field — refusing to write on any failure; all 160 files passed. Live checks: `ctx tasks sync` zero parse failures, `ctx tasks show 0063.1` prints the three labeled sections in canonical order, a synthetic 0.1 file is rejected naming both versions.
- Brief-writer verification against the working tree: `grep -rl 'schema-version = "0.2"'` matches exactly 160 board files; the only remaining `"0.1"` strings are inside fenced code examples in two archived files' prose (0036, 0059); `SCHEMA_VERSION` is `"0.2"` at `modules/core/src/task/mod.rs:20`; no `contains(WALL_LABEL)` remains in `markdown.rs`; the diff spans 171 files (160 board TOML + 11 module files, +1226/−467).
- Per the no-behavior-freezing doctrine: no golden files or frozen header inventories were added — behavioral unit tests plus live checks only.

## What the review found

The reviewer loop ran multiple rounds. Two blockers were raised and cleared in the final round, both re-verified by the reviewer with their own tools: (1) a dprint format failure on a hand-wrapped closure in `markdown.rs` (`just test` now exit 0, recorded in the repo-gates slot); (2) the importer's wall detection matched the label as a substring anywhere in a line, which would have scraped prose *mentions* of `**Wall:**` — including 0063.1's own Decisions text — as declarations. The fix restricts matching to line-initial declarations and keys line removal to a parsed id; the reviewer confirmed the new test and re-ran the core suite (36 passed). One non-blocking edge was noted for the record: a bare `**Wall:**` line preceding a valid declaration would anchor detection on the bare line and import no wall — judged theoretical since at most one wall line exists per real board file. Final verdict: **approved**, zero blockers, no escalation; prior rounds' verified strengths (all 160 files at 0.2, `prose_sections()` as single canonical order, typed wall read, `closed` stamped only on live→closed transition, 0.1 rejection naming both versions) stand. The owner's gated briefing double-approved the round.
